These facts hold for every section below. A section repeats one only when it adds a detail.

- **Registry.** Slice 16 (`wip/slice-16`, not on main when this was written: `git fetch origin wip/slice-16`, then `git show FETCH_HEAD:src/recomp_rt/win/season_change.h`) gives the interface. A rule kind is a `SeasonRuleKind` (name and the hooks `new_game`, `loaded`, `season`, `entry`, `before`, `after`) and one line in `season_rule_kinds` of `season_change.c`. `before` runs ahead of `set_up_rules` (vtable +0x8c) and `League::create_fixtures` 0x6835c0 inside `start_new_season`, so a field that they read goes there. `after` with `started` 0 is a competition that waits (an international edition, an unfinished cup). `season_change_add_comp` puts a new object into an entry's array, only inside that entry's `entry` hook. A kind calls `season_change_news` with one sentence for each change the player sees (Q258). A kind that finds no row changes nothing, so the rules stay after the last row (Q248). Read the doc `docs/research/2026-10-17-season-change.md` on that branch before you write a kind. If slice 16 is on main when you start, use main.
- **Two paths for each rule.** A season game (start year not 2001, or changing rules on, as slice 15 defines it) gets the rules of the start season at a new game (`new_game` hook, or a wrap of the entry's setup function `create_*_comps` when the object must exist before the run to the start date 0x5cc850). With changing rules on, the rules then change at each season change. With changing rules off they stay (Q232). The base game (2001/02, changing rules off) and `RECOMP_SEASON_CODE=off` get none of it (Q342).
- **Objects.** Competitions are made once at a new game by the setup function of their league table entry (`2026-10-16-sweep-season-end.md` 2.2). The classes read fixed key id globals, not their own record, so a second object of one class takes the same clubs (`2026-10-16-sweep-europe.md` 2.3, point 1). A new competition needs a competition record, a key id of its own, an object, a save and a load. The original finds every record by its name at each load (0x60efd0), so a renamed record must go through `season_change_rename`.
- **New competitions (shared).** Slices 20, 21, 24, 26, 28 and 29 all need new competitions, and the ending of a competition (an idle object). The first of them to start writes the design doc (record, key id, object and vtable, save and load, idle state) and a shared module, for example `src/recomp_rt/win/season_comps.c` and `.h`. The lead names that slice in its start message. Every later slice reads the doc, uses the module and adds to it in its own small block. Before you build, check main for `season_comps.h`.
- **Addresses.** Every address below comes from the sweep or doc named next to it. Function map names are hints: read the code at the address before you rely on it, and cite it. A size or count that the original holds in an immediate or a fixed array is a site in the checked mechanisms (`RT_WRAP`, `callbacks.py`, `callsites.py`, `INSNS`), so the build stops when the address does not match. Never guess an address: write "unknown" and find it.
